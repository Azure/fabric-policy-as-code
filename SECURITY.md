# Security

## Supported versions

FPAC is currently an early-stage project and has not published a stable release.
Until versioned releases are available, security fixes are applied to the latest
commit on the `main` branch.

| Version | Supported |
| --- | --- |
| Latest `main` | Yes |
| Earlier commits and unmaintained forks | No |

After FPAC begins publishing versioned releases, this table will identify the
release lines receiving security updates.

## Microsoft security policy

Microsoft takes the security of our software products and services seriously,
which includes all source code repositories managed through our GitHub
organizations, including [Microsoft](https://github.com/microsoft),
[Azure](https://github.com/Azure), [DotNet](https://github.com/dotnet),
[AspNet](https://github.com/aspnet), [Xamarin](https://github.com/xamarin), and
[our GitHub organizations](https://opensource.microsoft.com/).

If you believe you have found a security vulnerability in any Microsoft-owned
repository that meets
[Microsoft's definition of a security vulnerability](https://aka.ms/opensource/security/definition),
please report it as described below.

## Reporting security issues

**Do not report security vulnerabilities through public GitHub issues.**

Instead, report them to the Microsoft Security Response Center (MSRC) at
[https://msrc.microsoft.com/create-report](https://aka.ms/opensource/security/create-report).

If you prefer to submit without logging in, send email to
[secure@microsoft.com](mailto:secure@microsoft.com). If possible, encrypt your
message with the MSRC PGP key, available from the
[Microsoft Security Response Center PGP Key page](https://aka.ms/opensource/security/pgpkey).

You should receive a response within 24 hours. If you do not, follow up by email
to ensure the original message was received. Additional information is available
at [microsoft.com/msrc](https://aka.ms/opensource/security/msrc).

Include as much of the following information as possible:

- Type of issue, such as credential exposure, command injection, or privilege
  escalation.
- Full paths of source files related to the issue.
- The affected tag, branch, commit, or direct source URL.
- Any special configuration required to reproduce the issue.
- Step-by-step reproduction instructions.
- Proof-of-concept or exploit code, if available.
- The impact of the issue and how an attacker might exploit it.

This information helps Microsoft triage the report more quickly.

If you are reporting for a bug bounty, more complete reports can contribute to a
higher bounty award. See the
[Microsoft Bug Bounty Program](https://aka.ms/opensource/security/bounty) for
active programs.

## Preferred language

We prefer security communications to be in English.
